# 项目端口管理

根 `pnpm dev` 的 `predev` 钩子先调用 `pnpm ports`，成功释放端口后才启动 Turbo。当前 pnpm 默认执行该生命周期，不再重复设置启用开关。

[config.ts](./config.ts) 仅维护清理脚本的默认目标：3000、3001。应用不导入此文件，Docs 和 Playground 分别通过自身 `.env` 中的 `VITE_PORT` 配置监听端口。改变应用开发端口后，应同步本脚本的默认清理目标，或通过参数明确指定本次要清理的端口；显式输入不会修改应用配置。三个公开配置包本身不监听端口。

```bash
# 清理当前项目的默认端口。
pnpm ports
# 只清理显式选择的多个端口，不同时处理默认端口。
pnpm ports 4000 5000
# 多端口也支持逗号与重复的选项，重复端口只处理一次。
pnpm ports -p 4000,5000 --port 6000
# 确认进程可立即终止后，显式使用 SIGKILL。
pnpm ports --force 4000 5000
# 查看帮助，不查询或终止进程。
pnpm ports --help
```

- 默认发送 SIGTERM，等待选定端口全部释放，最多等待 5 秒；未释放或权限不足时退出失败，阻止 dev 抢占启动。
- `--force` 直接使用 SIGKILL；只有显式指定时生效。
- macOS 和 Linux 使用系统 lsof，仅查询所选 TCP 监听端口；Windows 使用 PowerShell 的 Get-NetTCPConnection。
- 不按进程名称批量结束 Node.js，不影响其他未选择的端口。结束监听进程会使其服务退出，重新运行 dev 才会启动新服务。

测试仅创建并终止自己的临时监听进程，覆盖延迟退出、多个端口、未选端口保留、空闲端口、输入校验和无副作用帮助；不会在测试中清理真实项目端口。
