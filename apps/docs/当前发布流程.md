# 当前发布流程

本文档只记录**当前 package.json 脚本对应的正确发布流程**。

旧的逐条原始命令可以继续作为参考；日常发布优先看本文档。

## 发布包

当前仓库只发布两个 npm 包：

| 包名 | 目录 | 说明 |
| --- | --- | --- |
| `@zzjtnb/stylelint-config` | `packages/stylelint-config` | Stylelint 共享配置包。 |
| `@zzjtnb/eslint-config` | `packages/eslint-config` | ESLint Flat Config 共享配置包。 |

根目录 `package.json` 是私有 workspace，不发布。

## 快速发布流程

### 推荐：交互式发布

```bash
pnpm release
```

脚本会先让你选择发布范围：发布两个包、仅发布 ESLint 或仅发布 Stylelint；随后检查 npm 登录状态、比较本地与 npm 版本、交互式升级版本、执行对应检查、预览发布包、逐包发布并核验最终版本。某一步失败时只能重试或中止，不会静默跳过失败。

如果只发布一个包，脚本只检查和发布该包，不会因为另一个包的 ESLint、构建或类型检查失败而阻塞当前发布。

当本地版本高于 npm 版本时，脚本会先显示差异并暂停发布。例如 npm 是 `0.0.1`、本地是 `0.0.3`，可以选择：

- **继续发布**：确认 `0.0.3` 是有意跳过的版本，按当前版本发布。
- **修改版本**：重新输入正确的 `x.y.z` 版本号，脚本会重新查询 npm 状态。
- **中止**：不发布，也不修改当前文件。

所有交互菜单都支持方向键和 Enter，也保留字母快捷键；非交互终端会自动回退到文字输入。

如果本地版本曾经在 npm 发布后又被删除，npm 仍会保留该版本号的占用记录，不能再次发布。脚本会明确列出这些版本，并要求修改为未使用的版本号后再继续。

版本升级后脚本还会再次检查占用记录。例如从 `0.0.10` 选择 `major` 会得到 `1.0.0`；如果该版本历史上已经发布过，脚本会在发布前要求改成其他未占用版本。

### npm 的 24 小时保护期

npm 官方规则中的 24 小时限制针对**整包取消发布后重新发布**：整包被取消发布后，新的版本也可能在 24 小时内无法发布。这个限制不是“正常发布后需要等待 24 小时才会显示”，也不能释放已经使用过的版本号。详见 [npm Unpublish Policy](https://docs.npmjs.com/policies/unpublish/)。

交互式发布脚本遇到 registry 404 时会提示这可能是新包，也可能是整包取消发布后的保护期；如果发布命令明确返回 24 小时限制，脚本会直接停止并提示等待，不会反复重试。正常发布后的 registry 校验最多等待约 60 秒，超时只能说明尚未确认，不代表脚本可以把未确认的包当作发布成功。

### 未升级版本

```bash
pnpm -w run release:check
pnpm -w run version:patch
pnpm -w run release:pack
pnpm -w run release:whoami
pnpm -w run release:publish
pnpm -w run release:verify
```

### 已升级版本

```bash
pnpm -w run release:check

```

## 核心规则

- npm 发布只依赖包名和 `package.json` 里的 `version`。
- 当前发布流程不依赖 git。
- 当前发布流程不会自动 commit。
- 当前发布流程不会自动 tag。
- 当前发布流程不会自动 push。
- 根目录脚本负责同时操作两个发布包。
- 子包脚本负责操作当前包自己。
- 如果只操作一个包，直接用 `pnpm --filter <包名> run <脚本>`。
- 版本号遵循 [语义化版本 SemVer](https://semver.org/lang/zh-CN/)。

## SemVer 版本选择

本项目发布版本按 [语义化版本 SemVer](https://semver.org/lang/zh-CN/) 判断。

| 版本类型 | 示例 | 什么时候用 |
| --- | --- | --- |
| `patch` | `0.1.0` → `0.1.1` | 修 bug、修文档、修类型声明、小规则修正，不改变默认行为。 |
| `minor` | `0.1.1` → `0.2.0` | 新增能力、新增默认支持范围、新增导出，且保持向后兼容。 |
| `major` | `0.2.0` → `1.0.0` | 破坏性变更、删除公开能力、默认行为改变、使用者需要迁移。 |

简单判断：

- 不确定是不是破坏性变更时，先按 `minor` 或 `patch` 评估影响范围。
- 只影响内部实现、不影响使用方式时，通常是 `patch`。
- 新增可用能力但旧用法仍然可用时，通常是 `minor`。
- 旧配置、旧 Node / ESLint / Stylelint 版本或旧用法不能继续工作时，通常是 `major`。

## 当前脚本分层

### 根目录脚本

根目录脚本负责聚合两个发布包：

| 命令 | 作用 |
| --- | --- |
| `pnpm release:check` | 发布前完整检查。 |
| `pnpm version:patch` | 两个发布包各自按当前版本升级 patch，并同步 lockfile。 |
| `pnpm version:minor` | 两个发布包各自按当前版本升级 minor，并同步 lockfile。 |
| `pnpm version:major` | 两个发布包各自按当前版本升级 major，并同步 lockfile。 |
| `pnpm release:pack` | 两个发布包同时执行 `pack --dry-run`。 |
| `pnpm release:whoami` | 检查 npm 官方源登录账号。 |
| `pnpm release:publish` | 两个发布包按顺序发布到 npm。 |
| `pnpm release:verify` | 查询两个发布包在 npm 上的 latest 版本。 |

### 子包脚本

两个发布子包内部都有同名脚本：

| 子包命令 | 作用 |
| --- | --- |
| `pnpm run version:patch` | 当前包升级 patch，不做 git 操作。 |
| `pnpm run version:minor` | 当前包升级 minor，不做 git 操作。 |
| `pnpm run version:major` | 当前包升级 major，不做 git 操作。 |
| `pnpm run release:pack` | 当前包执行 `pnpm pack --dry-run`。 |
| `pnpm run release:publish` | 当前包发布到 npm 官方源。 |
| `pnpm run release:verify` | 查询当前包在 npm 上的 latest 版本。 |

## 版本策略：独立版本或手动同号

两个发布包不要求版本号一致。根目录 `version:*` 脚本只是同时对两个包执行同一种 SemVer 升级，每个包都会基于自己的当前版本递增。

如果希望两个包继续保持独立版本，直接使用根目录脚本即可：

```bash
# 两个包各自基于当前版本升级 patch。
pnpm version:patch
```

只有在明确希望两个包使用同一个版本号时，才需要手动指定固定版本，例如 `0.1.0`：

```bash
# 设置本次要统一使用的版本号。
VERSION=0.1.0

# 把 Stylelint 包版本直接设置为 0.1.0；不生成 git commit，不生成 git tag，也不检查 git 工作区。
pnpm --dir packages/stylelint-config version "$VERSION" --no-git-tag-version --no-git-checks

# 把 ESLint 包版本直接设置为 0.1.0；不生成 git commit，不生成 git tag，也不检查 git 工作区。
pnpm --dir packages/eslint-config version "$VERSION" --no-git-tag-version --no-git-checks

# 同步 pnpm-lock.yaml，确保 lockfile 记录新的 workspace 包版本。
pnpm install
```

## 日常发布：patch

适合场景：

- 修复规则问题。
- 修复文档。
- 修复类型声明。
- 不改变默认行为。
- 不新增大的能力。

执行流程：

```bash
# 执行完整发布前检查：构建、类型检查、lint、测试都会执行；文档包的 lint 会检查 Markdown。
pnpm release:check

# 两个发布包各自升级 patch 版本；例如某个包 0.1.0 → 0.1.1。
pnpm version:patch

# 预览两个发布包真正会上传到 npm 的文件；这里只检查，不会发布。
pnpm release:pack

# 检查当前 npm 官方源登录账号；能输出用户名才说明可以继续发布。
pnpm release:whoami

# 按顺序发布两个包到 npm 官方源。
pnpm release:publish

# 查询两个包在 npm 官方源上的 latest 版本，确认发布结果。
pnpm release:verify
```

## 日常发布：minor

适合场景：

- 新增配置能力。
- 新增默认支持范围。
- 新增导出能力。
- 向后兼容的较大优化。

执行流程：

```bash
# 执行完整发布前检查。
pnpm release:check

# 两个发布包各自升级 minor 版本；例如某个包 0.1.1 → 0.2.0。
pnpm version:minor

# 预览两个发布包内容。
pnpm release:pack

# 检查 npm 官方源登录账号。
pnpm release:whoami

# 发布两个包。
pnpm release:publish

# 验证 npm latest 版本。
pnpm release:verify
```

## 日常发布：major

适合场景：

- 默认行为发生破坏性变化。
- 最低 Node.js / ESLint / Stylelint 要求大幅提高。
- 删除原有公开能力。
- 使用者需要主动迁移。

执行流程：

```bash
# 执行完整发布前检查。
pnpm release:check

# 两个发布包各自升级 major 版本；例如某个包 0.2.0 → 1.0.0。
pnpm version:major

# 预览两个发布包内容。
pnpm release:pack

# 检查 npm 官方源登录账号。
pnpm release:whoami

# 发布两个包。
pnpm release:publish

# 验证 npm latest 版本。
pnpm release:verify
```

## 只操作一个包

根目录不需要写 `version:stylelint:patch`、`version:eslint:patch` 这种重复脚本。

只操作单包时，使用 `pnpm --filter` 调用子包内部脚本。

### 只发 Stylelint 包

```bash

pnpm release:check

# 只升级 @zzjtnb/stylelint-config 的 patch 版本。
pnpm --filter @zzjtnb/stylelint-config run version:patch

# 单包版本变化后，从根目录同步 lockfile。
pnpm install

# 只预览 @zzjtnb/stylelint-config 的发布包内容。
pnpm --filter @zzjtnb/stylelint-config run release:pack

# 检查 npm 官方源登录账号。
pnpm release:whoami

# 只发布 @zzjtnb/stylelint-config。
pnpm --filter @zzjtnb/stylelint-config run release:publish

# 只验证 @zzjtnb/stylelint-config 的 npm latest 版本。
pnpm --filter @zzjtnb/stylelint-config run release:verify
```

# 只运行 @zzjtnb/eslint-config 的构建、类型检查、lint、测试等可以按需执行；完整检查仍推荐先跑根目录 release:check。

## 子包脚本实际做了什么

### 版本脚本

```bash
# 当前包升级 patch 版本；例如 0.1.0 → 0.1.1；不生成 git commit/tag。
pnpm version patch --no-git-tag-version --no-git-checks

# 当前包升级 minor 版本；例如 0.1.1 → 0.2.0；不生成 git commit/tag。
pnpm version minor --no-git-tag-version --no-git-checks

# 当前包升级 major 版本；例如 0.2.0 → 1.0.0；不生成 git commit/tag。
pnpm version major --no-git-tag-version --no-git-checks
```

### 发布脚本

```bash
# 当前包预览 npm 打包内容；不会上传 npm。
pnpm pack --dry-run

# 当前包发布到 npm 官方源；public 表示公开包，latest 表示默认安装版本。
# --no-git-checks 表示允许在未提交工作区中发布，不依赖 git 状态。
pnpm publish --access public --tag latest --registry https://registry.npmjs.org/ --no-git-checks
```

### 验证脚本

```bash
# Stylelint 包查询 npm latest 版本。
pnpm view @zzjtnb/stylelint-config version --registry https://registry.npmjs.org/

# ESLint 包查询 npm latest 版本。
pnpm view @zzjtnb/eslint-config version --registry https://registry.npmjs.org/
```

这些脚本依赖 `turbo.json` 里存在以下任务：

```json
{
  "version:patch": {
    "cache": false,
    "outputs": []
  },
  "version:minor": {
    "cache": false,
    "outputs": []
  },
  "version:major": {
    "cache": false,
    "outputs": []
  },
  "release:pack": {
    "cache": false,
    "outputs": []
  },
  "release:publish": {
    "cache": false,
    "outputs": []
  },
  "release:verify": {
    "cache": false,
    "outputs": []
  }
}
```

这里必须关闭缓存，因为版本更新、打包预览、发布、远程查询都不能使用历史缓存结果。

## 发布后如果只成功了一个包

如果 `pnpm release:publish` 第一个包成功、第二个包失败，不要直接重复执行完整发布命令。

原因：已经成功的包再次发布同版本会报 `version already exists`。

只重试失败的包即可：

```bash
# 如果失败的是 @zzjtnb/stylelint-config，只重试 Stylelint 包发布。
pnpm --filter @zzjtnb/stylelint-config run release:publish

# 如果失败的是 @zzjtnb/eslint-config，只重试 ESLint 包发布。
pnpm --filter @zzjtnb/eslint-config run release:publish
```

## Git 是可选记录

发布完成后，版本号和 lockfile 变化会留在本地。

是否提交、是否打 tag，由维护者自己决定。

这不是 npm 发布条件。

如果要记录源码版本：

```bash
# 把版本号和 lockfile 变化加入暂存区。
git add packages/stylelint-config/package.json packages/eslint-config/package.json pnpm-lock.yaml

# 创建普通提交记录本次发布版本。
git commit -m "chore: release v0.1.0"
```

如果要额外保留 tag：

```bash
# 创建本地 tag，方便以后从 git 历史定位这个 npm 版本。
git tag v0.1.0

# 推送源码提交。
git push origin master

# 推送 tag。
git push origin v0.1.0
```

## 常见问题

### npm 未登录或账号无权限

发布前必须先让 `release:whoami` 输出有权限的 npm 账号：

```bash
# 检查是否登录 npm 官方源。
pnpm release:whoami

# 如果未登录，登录 npm 官方源。
pnpm login --registry https://registry.npmjs.org/
```

如果 `pnpm publish` 阶段出现 `401 Unauthorized`、`403 Forbidden` 或 `404 Not Found - PUT https://registry.npmjs.org/<package>`，先不要重试发布。优先重新执行：

```bash
pnpm release:whoami
```

如果 `whoami` 失败或账号不是包的 maintainer，需要重新登录或切换到有发布权限的 npm 账号。

### registry 是镜像源

发布脚本已经显式指定：

```bash
--registry https://registry.npmjs.org/
```

所以即使本机默认 registry 是国内镜像，也不会影响 publish。

### 版本已存在

npm 不允许覆盖同一个版本。

处理方式：

```bash
# 查询当前 npm latest 版本。
pnpm release:verify

# 升级到新版本，例如 patch。
pnpm version:patch

# 重新预览并发布。
pnpm release:pack
pnpm release:publish
```

### 首次发布 @zzjtnb/eslint-config

如果查询 `@zzjtnb/eslint-config` 报 404，可能只是说明还没发布过。

首次发布前确认：

- `packages/eslint-config/package.json` 的 `version` 不是 `0.0.0`。
- `name` 是 `@zzjtnb/eslint-config`。
- `exports` 包含 `types`、`import`、`default`。
- `files` 只包含需要发布的文件。
- 发布脚本包含 `--access public`。
