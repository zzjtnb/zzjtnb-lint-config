# 原始发布流程

本文档记录本仓库 npm 包的**无 Git 依赖发布流程**。

核心原则：**npm 发布只依赖包名和 `package.json` 里的 `version`，不依赖 git commit、git tag 或 GitHub Release。**

本仓库是 pnpm workspace monorepo，根目录是私有工作区，不发布；真正发布到 npm 的包只有：

| 包名 | 目录 | 当前定位 |
| --- | --- | --- |
| `stylelint-config-zzjtnb` | `packages/stylelint-config` | Stylelint 17 共享配置 |
| `eslint-config-zzjtnb` | `packages/eslint-config` | ESLint 10 Flat Config 共享配置 |

## 最短发布流程

同步发布两个包时，只需要执行下面这一组命令。每一行都带了注释，方便确认它到底在做什么。

```bash
# 设置本次要发布的版本号；后面的命令都会读取这个变量。
VERSION=0.1.0

# 安装并同步 workspace 依赖；如果 package.json 或 lockfile 有变化，这一步会更新 node_modules。
pnpm install

# 运行所有包的 TypeScript / JSDoc 类型检查，确认导出的类型声明没有问题。
pnpm check-types

# 运行所有包的 lint；本仓库内部 lint 会自动修复可修复问题，并对 warning 使用严格检查。
pnpm lint

# 运行所有包的测试；当前主要用于确认配置包可以被 Node 正常加载。
pnpm test

# 运行 Markdown 检查并自动修复可修复问题，确保 README 和文档格式正确。
pnpm lint:markdownlint

# 把 stylelint-config-zzjtnb 的 package.json version 改成本次版本；--no-git-tag-version 表示不创建 git tag。
pnpm --dir packages/stylelint-config version "$VERSION" --no-git-tag-version

# 把 eslint-config-zzjtnb 的 package.json version 改成本次版本；同样不做任何 git 操作。
pnpm --dir packages/eslint-config version "$VERSION" --no-git-tag-version

# 版本号变化后重新同步 lockfile，避免 package.json 和 pnpm-lock.yaml 不一致。
pnpm install

# 预览 stylelint-config-zzjtnb 真正会发布到 npm 的文件；这一步不会发布，只是 dry-run。
pnpm --dir packages/stylelint-config pack --dry-run

# 预览 eslint-config-zzjtnb 真正会发布到 npm 的文件；确认不要把测试、缓存、node_modules 发出去。
pnpm --dir packages/eslint-config pack --dry-run

# 检查当前 npm 登录账号；必须能输出用户名，否则后面的 publish 会失败。
pnpm whoami --registry https://registry.npmjs.org/

# 发布 stylelint-config-zzjtnb 到 npm；--access public 表示公开包，--tag latest 表示默认安装版本。
pnpm --dir packages/stylelint-config publish --access public --tag latest --registry https://registry.npmjs.org/

# 发布 eslint-config-zzjtnb 到 npm；显式指定官方 registry，避免本机镜像源导致发布失败。
pnpm --dir packages/eslint-config publish --access public --tag latest --registry https://registry.npmjs.org/

# 查询 npm 上 stylelint-config-zzjtnb 的最新版本，确认发布结果已经生效。
pnpm view stylelint-config-zzjtnb version --registry https://registry.npmjs.org/

# 查询 npm 上 eslint-config-zzjtnb 的最新版本，确认发布结果已经生效。
pnpm view eslint-config-zzjtnb version --registry https://registry.npmjs.org/
```

这套流程不会自动执行任何 git 操作：

- 不自动 commit。
- 不自动 tag。
- 不自动 push。
- 不依赖 GitHub Release。

发布完成后，如果你想把版本号变更记录进仓库，再自己决定是否提交。

## 环境要求

| 项目 | 要求 | 为什么需要 |
| --- | --- | --- |
| Node.js | `>=22.13` | 根目录 `package.json` 已声明这个运行要求，pnpm 11 也需要较新的 Node。 |
| pnpm | `>=11` | 当前根目录 `packageManager` 是 `pnpm@11.1.3`。 |
| npm 账号 | 对两个 npm 包有发布权限 | 没有 maintainer 权限会发布失败。 |
| registry | `https://registry.npmjs.org/` | 国内镜像通常只读，不能 publish。 |

检查环境：

```bash
# 查看当前 Node.js 版本，确认满足根目录 engines.node 的要求。
node -v

# 查看当前 pnpm 版本，确认满足根目录 engines.pnpm 的要求。
pnpm -v

# 查看当前默认 npm registry；如果是 npmmirror，发布时必须显式指定官方 registry。
pnpm config get registry

# 查看当前是否已经登录 npm 官方源；能输出用户名才说明登录有效。
pnpm whoami --registry https://registry.npmjs.org/
```

如果没有登录：

```bash
# 登录 npm 官方源；发布权限和登录状态都以这个 registry 为准。
pnpm login --registry https://registry.npmjs.org/
```

## 版本策略

两个包可以同时发版，也可以独立发版；版本号不要求一致。

| 变更类型 | 版本类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| 文档、小修复、规则 bug 修复 | patch | `0.1.0` → `0.1.1` | 不改变主要能力。 |
| 新增配置包、新增默认能力、较大优化 | minor | `0.0.8` → `0.1.0` | 向后兼容的新能力。 |
| 默认行为破坏性变化、最低运行环境大幅提高 | major | `0.1.0` → `1.0.0` | 使用者需要主动迁移。 |

如果明确希望两个包使用同一个版本号，可以手动指定固定版本，例如：

```text
stylelint-config-zzjtnb@0.1.0
eslint-config-zzjtnb@0.1.0
```

## 发布前验证

发布前只验证 npm 包本身，不要求工作区干净，也不要求存在 git tag。

```bash
# 安装依赖并同步 lockfile，确保本地环境和 package.json 一致。
pnpm install

# 检查 JS 配置文件和 .d.ts 类型声明是否能被 TypeScript 正确理解。
pnpm check-types

# 检查 JS、TS、Vue、HTML、JSON、YAML 等文件的 ESLint 规则。
pnpm lint

# 运行测试脚本，确认配置包入口能被正常加载。
pnpm test

# 检查 Markdown 文档格式，避免 README 发布到 npm 后格式不规范。
pnpm lint:markdownlint
```

人工确认：

- [ ] 根目录 `LICENSE` 存在，且与两个包的 `license` 字段一致。
- [ ] 两个包的 `README.md` 和 `README.zh-CN.md` 已更新。
- [ ] 两个包的 `exports` 同时包含 `types`、`import`、`default`。
- [ ] 两个发布子包没有 `devDependencies`。
- [ ] `peerDependencies` 只声明使用者必须安装的主工具：`eslint` 或 `stylelint`。
- [ ] `dependencies` 只包含共享配置运行时真正需要加载的包。

## 更新版本号

使用 `pnpm version` 时必须加 `--no-git-tag-version`，让它只改版本号，不执行 git commit/tag。

`pnpm version` 支持两类写法：

| 写法 | 示例 | 作用 |
| --- | --- | --- |
| 固定版本号 | `version 0.1.0` | 直接把版本号设置成指定值。 |
| 版本类型 | `version patch` / `version minor` / `version major` | 按 SemVer 自动递增版本号。 |

版本类型含义：

| 类型 | 示例 | 适合场景 |
| --- | --- | --- |
| `patch` | `0.1.0` → `0.1.1` | bug 修复、文档修正、小规则修复。 |
| `minor` | `0.1.0` → `0.2.0` | 新增能力、默认支持范围增强、向后兼容优化。 |
| `major` | `0.1.0` → `1.0.0` | 破坏性变更、默认行为改变、使用者需要迁移。 |
| `prepatch` | `0.1.0` → `0.1.1-0` | 下一个 patch 的预发布版本。 |
| `preminor` | `0.1.0` → `0.2.0-0` | 下一个 minor 的预发布版本。 |
| `premajor` | `0.1.0` → `1.0.0-0` | 下一个 major 的预发布版本。 |
| `prerelease` | `0.2.0-beta.0` → `0.2.0-beta.1` | 在已有预发布版本上继续递增。 |

### 需要手动同号时：使用固定版本号

如果目标是把两个包设置成同一个版本号，不要直接用 `patch` / `minor` / `major`，因为它们会基于各自当前版本分别递增，不能自动对齐。

例如当前如果是：

```text
stylelint-config-zzjtnb@0.0.8
eslint-config-zzjtnb@0.0.0
```

直接执行 `patch` 会变成：

```text
stylelint-config-zzjtnb@0.0.9
eslint-config-zzjtnb@0.0.1
```

所以需要同号时推荐直接指定同一个版本号：

```bash
# 设置本次两个包都要使用的固定版本号。
VERSION=0.1.0

# 把 stylelint-config-zzjtnb 的 version 直接设置为 0.1.0；不自动 commit，不自动 tag。
pnpm --dir packages/stylelint-config version "$VERSION" --no-git-tag-version

# 把 eslint-config-zzjtnb 的 version 直接设置为 0.1.0；不自动 commit，不自动 tag。
pnpm --dir packages/eslint-config version "$VERSION" --no-git-tag-version

# 重新生成 / 同步 pnpm-lock.yaml，确保 lockfile 记录到新的 workspace 版本。
pnpm install
```

### 同时升级 patch

需要同时给两个包发布 patch 时，可以分别执行 patch 升级。

```bash
# 把 stylelint-config-zzjtnb 从当前版本升级到下一个 patch 版本；例如 0.1.0 → 0.1.1。
pnpm --dir packages/stylelint-config version patch --no-git-tag-version

# 把 eslint-config-zzjtnb 从当前版本升级到下一个 patch 版本；例如 0.1.0 → 0.1.1。
pnpm --dir packages/eslint-config version patch --no-git-tag-version

# 同步 pnpm-lock.yaml，确保 workspace 版本记录一致。
pnpm install
```

### 同时升级 minor

新增能力、默认支持增强、向后兼容优化时，可以同时给两个包分别升级 minor。

```bash
# 把 stylelint-config-zzjtnb 从当前版本升级到下一个 minor 版本；例如 0.1.1 → 0.2.0。
pnpm --dir packages/stylelint-config version minor --no-git-tag-version

# 把 eslint-config-zzjtnb 从当前版本升级到下一个 minor 版本；例如 0.1.1 → 0.2.0。
pnpm --dir packages/eslint-config version minor --no-git-tag-version

# 同步 pnpm-lock.yaml，确保 workspace 版本记录一致。
pnpm install
```

### 同时升级 major

默认行为发生破坏性变化，或最低环境要求大幅提高时，才升级 major。

```bash
# 把 stylelint-config-zzjtnb 从当前版本升级到下一个 major 版本；例如 0.2.0 → 1.0.0。
pnpm --dir packages/stylelint-config version major --no-git-tag-version

# 把 eslint-config-zzjtnb 从当前版本升级到下一个 major 版本；例如 0.2.0 → 1.0.0。
pnpm --dir packages/eslint-config version major --no-git-tag-version

# 同步 pnpm-lock.yaml，确保 workspace 版本记录一致。
pnpm install
```

### 使用 pnpm recursive 同时升级

也可以用 `--recursive` 和 `--filter` 一条命令同时升级两个发布包；每个包仍然基于自己的当前版本递增。

```bash
# 同时把两个发布包升级到下一个 patch 版本；--filter 限定只处理这两个包。
pnpm version patch --recursive --filter stylelint-config-zzjtnb --filter eslint-config-zzjtnb --no-git-tag-version

# 同步 pnpm-lock.yaml，确保 workspace 版本记录一致。
pnpm install
```

```bash
# 同时把两个发布包升级到下一个 minor 版本；适合新增向后兼容能力。
pnpm version minor --recursive --filter stylelint-config-zzjtnb --filter eslint-config-zzjtnb --no-git-tag-version

# 同步 pnpm-lock.yaml，确保 workspace 版本记录一致。
pnpm install
```

```bash
# 同时把两个发布包升级到下一个 major 版本；只在破坏性变更时使用。
pnpm version major --recursive --filter stylelint-config-zzjtnb --filter eslint-config-zzjtnb --no-git-tag-version

# 同步 pnpm-lock.yaml，确保 workspace 版本记录一致。
pnpm install
```

### 只发布 Stylelint 配置

```bash
# 只把 packages/stylelint-config/package.json 的 version 升级到下一个 patch 版本。
pnpm --dir packages/stylelint-config version patch --no-git-tag-version
```

## 打包内容预检

发布前必须看 dry-run 输出，确认 npm 包里只包含应该发布的文件。

```bash
# 预览 stylelint-config-zzjtnb 发布包内容；不会真的上传 npm。
pnpm --dir packages/stylelint-config pack --dry-run

# 预览 eslint-config-zzjtnb 发布包内容；不会真的上传 npm。
pnpm --dir packages/eslint-config pack --dry-run
```

每个包都应该主要包含：

```text
README.md        # 英文说明文档，npm 包首页默认展示。
README.zh-CN.md  # 中文说明文档，方便中文使用者阅读。
index.js         # ESM 配置入口，用户实际 import / extends 的文件。
index.d.ts       # TypeScript 类型声明，提供编辑器提示。
package.json     # npm 包元信息，包括 name、version、exports、dependencies。
```

不应该包含：

```text
node_modules  # 本地依赖目录，不能发布。
tests         # 仓库测试文件，用户安装配置包不需要。
fixtures      # 测试样例文件，用户安装配置包不需要。
本地缓存      # 例如 .cache，不能发布。
临时文件      # 调试或本地生成文件，不能发布。
```

## 正式发布

发布时从对应包目录执行 `pnpm publish`，避免递归发布 workspace 里的 demo 或测试包。

### 同步发布两个包

```bash
# 发布 Stylelint 配置包到 npm 官方源；latest 表示普通用户默认安装这个版本。
pnpm --dir packages/stylelint-config publish --access public --tag latest --registry https://registry.npmjs.org/

# 发布 ESLint 配置包到 npm 官方源；首次发布公开包时必须确保 access 是 public。
pnpm --dir packages/eslint-config publish --access public --tag latest --registry https://registry.npmjs.org/
```

### 只发布其中一个包

```bash
# 只发布 Stylelint 配置包；适合只改了 stylelint-config-zzjtnb 的情况。
pnpm --dir packages/stylelint-config publish --access public --tag latest --registry https://registry.npmjs.org/
```

或：

```bash
# 只发布 ESLint 配置包；适合只改了 eslint-config-zzjtnb 的情况。
pnpm --dir packages/eslint-config publish --access public --tag latest --registry https://registry.npmjs.org/
```

参数说明：

- `--dir packages/stylelint-config`：让 pnpm 在 Stylelint 子包目录执行命令。
- `--dir packages/eslint-config`：让 pnpm 在 ESLint 子包目录执行命令。
- `publish`：把当前目录对应的 npm 包上传到 registry。
- `--access public`：公开发布，首次发布时尤其建议显式写上。
- `--tag latest`：把这个版本标记为默认安装版本。
- `--registry https://registry.npmjs.org/`：强制使用 npm 官方源，避免镜像源发布失败。

## 发布后验证

检查 npm 上的版本：

```bash
# 查看 npm 官方源上 stylelint-config-zzjtnb 当前 latest 版本。
pnpm view stylelint-config-zzjtnb version --registry https://registry.npmjs.org/

# 查看 npm 官方源上 eslint-config-zzjtnb 当前 latest 版本。
pnpm view eslint-config-zzjtnb version --registry https://registry.npmjs.org/
```

检查包元信息：

```bash
# 查看 stylelint-config-zzjtnb 发布后的 peerDependencies、dependencies 和 engines 是否正确。
pnpm view stylelint-config-zzjtnb peerDependencies dependencies engines --registry https://registry.npmjs.org/

# 查看 eslint-config-zzjtnb 发布后的 peerDependencies、dependencies 和 engines 是否正确。
pnpm view eslint-config-zzjtnb peerDependencies dependencies engines --registry https://registry.npmjs.org/
```

如果需要真实安装验证，可以在临时目录测试：

```bash
# 创建一个临时验证目录，避免污染当前仓库。
mkdir /tmp/lint-config-verify

# 进入临时验证目录。
cd /tmp/lint-config-verify

# 初始化一个最小 package.json。
pnpm init

# 从 npm 安装刚发布的 ESLint / Stylelint 共享配置和对应 peer 工具。
pnpm add -D eslint eslint-config-zzjtnb stylelint stylelint-config-zzjtnb
```

ESLint 配置：

```js
// 导入 eslint-config-zzjtnb 默认导出的配置工厂函数。
import zzjtnb from 'eslint-config-zzjtnb'

// 使用默认配置：TypeScript、Vue、UnoCSS 默认启用，Markdown lint 默认交给 markdownlint-cli2。
export default zzjtnb()
```

Stylelint 配置：

```js
// 导出 Stylelint 配置对象。
export default {
  // 通过 extends 使用 stylelint-config-zzjtnb 共享配置入口。
  extends: [
    // 启用本包封装好的 CSS、SCSS、Vue、UnoCSS / Tailwind 风格和 rpx 支持。
    'stylelint-config-zzjtnb',
  ],
}
```

执行验证：

```bash
# 用临时项目安装到的 eslint 执行检查，确认 eslint-config-zzjtnb 能被正常加载。
pnpm exec eslint .

# 用临时项目安装到的 stylelint 执行检查，并指定标准缓存路径。
pnpm exec stylelint "**/*.{css,scss,vue,html}" --config stylelint.config.js --cache-location node_modules/.cache/.stylelintcache
```

## Git 是可选记录，不是发布条件

npm 发布完成后，版本号和 lockfile 变更会留在本地工作区。是否提交、是否打 tag，由维护者自己决定。

如果只想记录源码变更，可以提交：

```bash
# 把两个子包 package.json 和 lockfile 加入暂存区。
git add packages/stylelint-config/package.json packages/eslint-config/package.json pnpm-lock.yaml

# 创建一个普通提交，用来记录本次 npm 发布对应的版本号变化。
git commit -m "chore: release v0.1.0"
```

如果想保留 tag，也可以额外打 tag：

```bash
# 创建本地 tag，方便以后从 git 历史定位这个 npm 版本。
git tag v0.1.0

# 推送源码提交到远程 master。
git push origin master

# 推送 tag 到远程。
git push origin v0.1.0
```

但这些都不是 npm 发布的必要步骤。

## 常见问题

### 发布失败：未登录或权限不足

现象通常是：

- `401 Unauthorized`
- `403 Forbidden`
- `404 Not Found - PUT https://registry.npmjs.org/<package>`
- 提示没有发布权限

其中发布阶段的 `404 Not Found - PUT ...` 不等同于“包不存在”，也可能是当前 npm token 无效、未登录或账号没有该包权限。

```bash
# 检查当前 npm 官方源登录状态。
pnpm whoami --registry https://registry.npmjs.org/

# 如果没有登录或登录账号不对，重新登录 npm 官方源。
pnpm login --registry https://registry.npmjs.org/
```

如果仍然失败，查询并确认当前账号是否是 maintainer：

```bash
pnpm view stylelint-config-zzjtnb maintainers --json --registry https://registry.npmjs.org/
pnpm view eslint-config-zzjtnb maintainers --json --registry https://registry.npmjs.org/
```

### 发布失败：registry 是镜像源

国内镜像通常是只读的，不能 publish。发布命令里显式加官方 registry 即可：

```bash
# 指定 npm 官方源发布，绕过本机默认 registry 配置。
pnpm --dir packages/stylelint-config publish --registry https://registry.npmjs.org/
```

### 发布失败：版本已存在

npm 不允许覆盖同一个版本。

处理方式：

1. 查询当前 npm 版本。
2. 提升到一个新版本号。
3. 重新执行验证和 dry-run。
4. 再发布。

```bash
# 查询 stylelint-config-zzjtnb 当前 npm latest 版本。
```

### 首次发布 `eslint-config-zzjtnb`

如果查询版本时报 404，可能说明包还没有发布过。

首次发布前确认：

- 包名可用。
- `version` 不是 `0.0.0`。
- `description`、`keywords`、`repository`、`bugs`、`license` 完整。
- 发布命令带了 `--access public`。

### 发布后发现问题

优先使用 deprecate，而不是 unpublish：

```bash
# 标记 stylelint-config-zzjtnb 的问题版本为废弃，并提示用户升级。
pnpm deprecate stylelint-config-zzjtnb@0.1.0 "This version has a known issue. Please upgrade."
```
