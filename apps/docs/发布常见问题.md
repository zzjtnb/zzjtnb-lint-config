# 发布常见问题

本文档记录当前项目发布过程中常见问题的排查和处理方式。

处理原则：

- 不包含 Git tag、GitHub Release、自动推送等内容。
- 命令统一使用 `pnpm`。
- 发布命令统一显式指定 npm 官方源。
- 同时覆盖 `@zzjtnb/stylelint-config` 和 `@zzjtnb/eslint-config` 两个发布包。

## 发布失败：401 / 403 / 404 PUT

### 原因

如果 `pnpm publish` 在 `PUT https://registry.npmjs.org/<package>` 阶段失败，常见根因是 npm 官方源未登录、登录账号不对，或者当前账号不是该包 maintainer。

> 注意：发布阶段的 `404 Not Found - PUT ...` 不等同于“包不存在”。npm registry 可能在未认证或无权限时返回 404/403 类错误。先查登录状态，不要直接重试发布。

### 处理方式

先检查 npm 官方源登录状态：

```bash
# 项目脚本封装的登录检查。
pnpm release:whoami

# 或直接查询 npm 官方源当前登录账号。
pnpm whoami --registry https://registry.npmjs.org/
```

如果返回 `401 Unauthorized`、没有用户名，或用户名不是有权限的账号，重新登录：

```bash
pnpm login --registry https://registry.npmjs.org/
```

登录后再次确认：

```bash
pnpm release:whoami
```

如果已经登录但仍然失败，查询包的 maintainer，确认当前账号是否有发布权限：

```bash
pnpm view @zzjtnb/stylelint-config maintainers --json --registry https://registry.npmjs.org/
pnpm view @zzjtnb/eslint-config maintainers --json --registry https://registry.npmjs.org/
```

只有 `release:whoami` 能输出正确账号后，才继续执行：

```bash
pnpm release:publish
```

## 查询包版本返回 404

### 原因

`pnpm view <package> version` 返回 404 只说明 npm 官方源当前查不到这个包或这个包名；首次发布新包前可能出现这种情况。

这和 `pnpm publish` 阶段的 `404 Not Found - PUT ...` 不是同一个问题。发布阶段 404 应优先按“未登录或无权限”排查。

### 处理方式

先确认查询的是 npm 官方源：

```bash
pnpm view @zzjtnb/stylelint-config version --registry https://registry.npmjs.org/
pnpm view @zzjtnb/eslint-config version --registry https://registry.npmjs.org/
```

如果确认是首次发布新包，发布前检查：

- `package.json` 的 `name` 是目标包名。
- `version` 不是 `0.0.0`。
- `files`、`exports`、`main`、`types` 配置正确。
- 发布命令包含 `--access public`。
- `pnpm release:whoami` 能输出有权限的 npm 账号。

## 发布失败：版本已经存在

### 原因

npm 不允许覆盖已经发布过的同一个版本。

例如已经发布过：

```text
@zzjtnb/stylelint-config@0.1.0
```

再次发布同一个版本就会失败。

### 处理方式

先查看 npm 官方源上的当前版本：

```bash
# 查看 Stylelint 配置包当前 latest 版本。
pnpm view @zzjtnb/stylelint-config version --registry https://registry.npmjs.org/

# 查看 ESLint 配置包当前 latest 版本。
pnpm view @zzjtnb/eslint-config version --registry https://registry.npmjs.org/
```

然后升级到新的版本号。

同时升级两个包时：

```bash
# 两个发布包各自基于当前版本升级 patch。
pnpm version:patch
```

只升级其中一个包时：

```bash
# 只升级 Stylelint 配置包的 patch 版本。
pnpm --filter @zzjtnb/stylelint-config run version:patch

# 单包版本变化后同步 lockfile。
pnpm install
```

或者：

```bash
# 只升级 ESLint 配置包的 patch 版本。
pnpm --filter @zzjtnb/eslint-config run version:patch

# 单包版本变化后同步 lockfile。
pnpm install
```

升级后重新预览并发布：

```bash
# 预览发布包内容。
pnpm release:pack

# 发布两个包。
pnpm release:publish
```

## 两个包只发布成功了一个

### 原因

`pnpm release:publish` 会依次发布两个包。如果第一个包已经发布成功，第二个包失败，不能直接重复执行完整发布命令。

否则已经成功的包会因为同版本已存在而再次失败。

### 处理方式

只重试失败的那个包。

```bash
# 如果失败的是 @zzjtnb/stylelint-config，只重试 Stylelint 包。
pnpm --filter @zzjtnb/stylelint-config run release:publish

# 如果失败的是 @zzjtnb/eslint-config，只重试 ESLint 包。
pnpm --filter @zzjtnb/eslint-config run release:publish
```

发布后再验证：

```bash
# 验证两个包的 npm latest 版本。
pnpm release:verify
```

## 发布成功但搜索不到包

### 原因

常见原因：

1. npm 页面或搜索索引有延迟。
2. 本地默认 registry 是国内镜像，镜像同步 npm 官方源存在延迟。
3. 安装时没有显式指定官方源，实际查的是镜像源。

### 处理方式

优先查询 npm 官方源：

```bash
# 直接从 npm 官方源查询 Stylelint 配置包。
pnpm view @zzjtnb/stylelint-config version --registry https://registry.npmjs.org/

# 直接从 npm 官方源查询 ESLint 配置包。
pnpm view @zzjtnb/eslint-config version --registry https://registry.npmjs.org/
```

如果官方源能查到，说明发布已经成功。镜像源同步慢不是发布问题。

可以在临时目录里从官方源安装验证：

```bash
# 创建临时测试目录。
mkdir /tmp/lint-config-install-test

# 进入临时测试目录。
cd /tmp/lint-config-install-test

# 初始化 package.json。
pnpm init

# 从 npm 官方源安装刚发布的两个配置包和对应 peer 工具。
pnpm add -D eslint @zzjtnb/eslint-config stylelint @zzjtnb/stylelint-config --registry https://registry.npmjs.org/
```

## 发布失败：No workspaces found

### 原因

通常是当前命令运行目录不对，或者 workspace 配置没有被 pnpm 识别。

本仓库的 workspace 配置在根目录：

```text
pnpm-workspace.yaml
```

### 处理方式

先确认当前在仓库根目录：

```bash
# 查看当前目录。
pwd

# 查看 workspace 配置是否存在。
ls pnpm-workspace.yaml
```

推荐使用当前根目录脚本，不直接手写递归发布：

```bash
# 预览两个发布包。
pnpm release:pack

# 发布两个发布包。
pnpm release:publish
```

如果只发布某一个包，用 filter 调子包脚本：

```bash
# 只发布 Stylelint 配置包。
pnpm --filter @zzjtnb/stylelint-config run release:publish

# 只发布 ESLint 配置包。
pnpm --filter @zzjtnb/eslint-config run release:publish
```

## 如何发布测试版本

测试版本应该发布到 npm 的非 `latest` dist-tag，例如 `next`。

> 注意：这里的 `--tag next` 是 npm dist-tag，不是 Git tag。

### Stylelint 包测试版本

```bash
# 进入 Stylelint 包目录并升级预发布版本，例如 0.1.1-beta.0。
pnpm --dir packages/stylelint-config version prepatch --preid beta --no-git-tag-version --no-git-checks

# 同步 lockfile。
pnpm install

# 预览包内容。
pnpm --filter @zzjtnb/stylelint-config run release:pack

# 发布到 npm 的 next 标签。
pnpm --dir packages/stylelint-config publish --access public --tag next --registry https://registry.npmjs.org/
```

### ESLint 包测试版本

```bash
# 进入 ESLint 包目录并升级预发布版本，例如 0.1.1-beta.0。
pnpm --dir packages/eslint-config version prepatch --preid beta --no-git-tag-version --no-git-checks

# 同步 lockfile。
pnpm install

# 预览包内容。
pnpm --filter @zzjtnb/eslint-config run release:pack

# 发布到 npm 的 next 标签。
pnpm --dir packages/eslint-config publish --access public --tag next --registry https://registry.npmjs.org/
```

用户安装测试版本：

```bash
# 安装 Stylelint 配置包的 next 版本。
pnpm add -D @zzjtnb/stylelint-config@next --registry https://registry.npmjs.org/

# 安装 ESLint 配置包的 next 版本。
pnpm add -D @zzjtnb/eslint-config@next --registry https://registry.npmjs.org/
```

## 如何验证发布是否成功

推荐先用项目脚本：

```bash
# 查询两个包在 npm 官方源上的 latest 版本。
pnpm release:verify
```

也可以分别查询：

```bash
# 查询 Stylelint 配置包版本。
pnpm view @zzjtnb/stylelint-config version --registry https://registry.npmjs.org/

# 查询 ESLint 配置包版本。
pnpm view @zzjtnb/eslint-config version --registry https://registry.npmjs.org/
```

查看完整包信息：

```bash
# 查看 Stylelint 配置包完整信息。
pnpm view @zzjtnb/stylelint-config --registry https://registry.npmjs.org/

# 查看 ESLint 配置包完整信息。
pnpm view @zzjtnb/eslint-config --registry https://registry.npmjs.org/
```

真实安装测试：

```bash
# 创建临时测试目录。
mkdir /tmp/lint-config-verify

# 进入临时测试目录。
cd /tmp/lint-config-verify

# 初始化 package.json。
pnpm init

# 安装两个配置包和对应 peer 工具。
pnpm add -D eslint @zzjtnb/eslint-config stylelint @zzjtnb/stylelint-config --registry https://registry.npmjs.org/
```

## 如何撤销或标记问题版本

优先使用 deprecate，不要轻易 unpublish。

```bash
# 标记 Stylelint 配置包的问题版本为废弃。
pnpm deprecate @zzjtnb/stylelint-config@0.1.0 "This version has a known issue. Please upgrade."

# 标记 ESLint 配置包的问题版本为废弃。
pnpm deprecate @zzjtnb/eslint-config@0.1.0 "This version has a known issue. Please upgrade."
```

然后发布一个修复版本：

```bash
# 两个包各自基于当前版本升级 patch。
pnpm version:patch

# 预览发布内容。
pnpm release:pack

# 发布修复版本。
pnpm release:publish

# 验证 npm latest 版本。
pnpm release:verify
```

只有在刚发布且确认必须移除时，才考虑 unpublish。不要删除已经被用户依赖的稳定版本。
