# Lint Lab

在浏览器里体验 ESLint、Stylelint 和 Markdownlint 共享配置。编辑示例代码，用真实引擎检查并自动修复，查看每个文件实际生效的规则，再把配置复制到自己的项目。

## 启动

这是本仓库的本地工作台，不是安装到消费项目中的公开包。Node.js 与 pnpm 要求以仓库根 `package.json` 的 `engines`、`packageManager` 为准；公开配置包的最低消费环境不能代替仓库开发环境。

在仓库根目录安装依赖并启动：

```bash
pnpm install
pnpm --filter @zzjtnb/playground dev
```

打开 <http://localhost:3001/>。开发服务固定使用 3001 端口，端口被占用时会直接报错而不是自动换端口，请先释放该端口。终端中的 `Local` 地址供本机访问，`Network` 地址可供同一网络中的其他设备访问。服务监听所有网卡，仅在可信的本机或局域网使用；这不是带认证、配额和隔离能力的公网托管运行器。

页面和代码检查服务由同一个命令启动，无需单独配置后端。代码实验读取本仓库当前共享配置源码，不要求先构建公开包；它不是把浏览器里的草稿写到磁盘后再运行 CLI。

## 支持的文件

按 **ESLint → Stylelint → Markdownlint** 选择工具，再选择该工具提供的文件类型：

| 工具 | 工作台提供的文件类型 |
| --- | --- |
| ESLint | TypeScript、JavaScript、Vue SFC、TOML、JSON、YAML |
| Stylelint | CSS、SCSS、Vue SFC、HTML |
| Markdownlint | Markdown |

这里使用预设虚拟文件名，不支持上传项目、导入任意文件路径或切换到任意项目目录。公开包支持的能力不等于工作台全部提供了对应入口；例如 ESLint 的 pnpm 集成在本地运行器中明确关闭，工作区专属规则应在真实消费项目中验证。

## 功能

页面分为三个视图，顶部可切换 ESLint、Stylelint 与 Markdownlint。

### 代码实验

选择文件类型并编辑代码，点击“运行检查”或按 Ctrl / ⌘ + Enter 查看诊断，点击某条诊断会定位到对应行。“自动修复”会把可修复的内容写回当前草稿，仍需手动处理的问题继续显示。

- 修改代码后，上一次结果会标记为“需重新检查”，旧诊断不再定位到已修改的代码。切换工具或文件、编辑正在检查的代码时，会放弃当前请求的结果，迟到结果不会覆盖新草稿。
- “取消等待”只让当前页面放弃等待和结果，不保证已经开始的服务端引擎计算立即停止。
- 结果可按错误或警告筛选；筛选结果为空只代表当前筛选没有匹配项，不代表检查通过。读取规则或检查失败时按页面提示重试，不能将失败当成零错误。
- “自动修复”只应用引擎支持的修复，并显示最终文本上仍存在的问题；显示已修复不等于全部问题已解决。
- 每个工具的每种文件类型各自保存草稿，“恢复示例”只恢复当前文件。
- 编辑器中 Tab 插入两个空格；按 Escape 后再按 Tab 可离开编辑器，Shift + Tab 同样可以离开。
- 桌面端拖动分隔线调整面板宽度，也可以聚焦分隔线后用方向键、Home、End 调整；手机端代码与结果上下排列。

### 配置接入

按页面中的三个步骤接入自己的项目：安装依赖、保存配置文件、运行项目检查。安装命令、检查命令和配置草稿都可以一键复制，“恢复当前配置草稿”只恢复当前工具。

页面不会自动安装依赖或修改你的项目文件；这里的命令需要在你的项目根目录执行。检查命令默认不写回文件，需要自动修复时在命令后追加 `--fix`，并核对项目本地配置是否覆盖修复选项。

接入示例与代码实验有不同职责：例如 ESLint 接入草稿设置 `markdown: false`，让项目中的 Markdownlint 负责文档；实验区不执行这份草稿。只使用 ESLint，或仍需检查 Markdown 代码块时，应按项目职责调整该选项，不能把 Markdownlint 当成代码块检查的替代。

### 规则参考

选择文件类型后，列出当前工具对该文件解析出的规则，可按规则名、插件或说明搜索，并筛选“已启用”或“未启用”。ESLint 和 Stylelint 列出当前文件配置中出现的规则，不是所有可安装插件的规则全集；Markdownlint 列出运行器已安装版本的内置规则，不加载消费项目的自定义规则。

规则较多时分批显示，点击“继续显示规则”查看剩余内容；搜索与筛选作用于完整的已读取列表，不只作用于当前显示批次。选择规则可查看处理方式和格式化后的配置值，并可复制；引擎提供文档地址的规则可直接跳转，未提供的规则只显示已有说明，不猜测链接。

规则标签描述违规时如何处理，不是当前代码的检查结果，也不是开关：

- **违规时报错**：代码违反这条规则时会被报告为错误。
- **违规时警告**：代码违反这条规则时会被报告为警告。
- **未启用**：这条规则不参与当前文件检查，不会产生诊断。

实际代码问题请在“代码实验”的结果中查看。

## 保存与分享

草稿、所选工具和文件、当前视图、规则搜索词及主题保存在当前浏览器的本地存储中，不会在设备或浏览器之间自动同步。浏览器禁止存储、空间不足或已有数据无效时，页面会提示保存或恢复失败；当前仍可编辑，不要把提示失败当作已经保存。

点击“分享工作区”会生成并复制快照链接。快照包含**全部工具的代码草稿和配置草稿，不仅是当前打开的文件**，以及所选工具、各工具所选文件、当前视图、搜索词和主题。链接中的内容只是编码，不是加密；分享前应检查整个工作区是否含敏感信息，而不只是当前编辑器。

接收方需要能访问链接中的工作台地址；`localhost` 只指向接收方自己的设备，生成链接不会上传草稿、部署服务或创建可公开访问的站点。接收方使用不同的本地地址时，可将链接中的路径和 `#` 后的完整快照保留在其可访问的工作台地址上；实际检查仍需要开发运行器。

检查结果、诊断、运行耗时、面板宽度和规则启用状态筛选不包含在快照中；打开链接后，需要重新运行检查。快照由链接本身携带，接收方的浏览器恢复内容后仍独立维护自己的草稿。

继续编辑并成功保存后，地址栏会移除旧快照，刷新读取最新本地草稿；已复制的链接仍保持原快照，分享新内容需重新生成。复制失败时页面会提示，分享链接仍可从地址栏手动复制；普通文本也可选中后手动复制。

## 使用限制

- 代码实验使用共享默认规则，输入只作为文本分析，不会被执行，也不会写回项目文件。配置草稿仅用于复制和分享，编辑它不会改变代码实验的规则。
- 单次代码输入不能超过 64 KiB，按 UTF-8 字节计算；完整 JSON 请求体另有 70,000 字节上限。换行、引号等字符在 JSON 中转义后可能使请求体先达到上限，不能仅按编辑器字符数判断。
- 检查和规则查询依赖开发服务。构建后的静态页面和 `vite preview` 不提供检查服务；页面提示运行器未连接时，请在仓库根目录运行 `pnpm --filter @zzjtnb/playground dev`。预览默认端口来自 Vite 当前配置，为 3001，端口被占用时直接报错。
- 修改共享配置源码后需要重启开发服务，才会重新加载引擎配置与规则。
