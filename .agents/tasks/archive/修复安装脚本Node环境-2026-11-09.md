# 修复安装脚本Node环境

- [x] T01 修复独立 pnpm 在缺少 nvm PATH 时无法执行安装守卫的问题。
  - 复现：仅保留 pnpm/bin 与系统目录的 PATH，执行安装守卫报 `node: command not found`。
  - 实现：通过 `pnpm runtime set node 26.13.0 --global` 准备本机全局 Node.js 入口；添加 `.nvmrc`，避免 pnpm 继承父目录 `.node-version` 中的 Node.js 18；README 说明版本选择和首次下载条件。
  - 验证：相同精简 PATH 下 `node --version` 返回 v26.13.0，`pnpm --config.verifyDepsBeforeRun=error run preinstall` 和 `pnpm install --frozen-lockfile` 均退出 0；README Markdownlint 和 `git diff --check` 通过。
  - 取舍：实测 pnpm 12.15.0 在准备项目运行时之前执行根 preinstall，因此撤回不能解决首次安装问题的 devEngines.runtime 试验。
  - 已有改动：上一轮自动安装使 pnpm-lock.yaml 同步用户已暂存的 ESLint、Stylelint catalog 更新，本轮保留；未改变暂存范围。
  - 验证范围：未执行完整依赖升级及全量类型检查、测试，本次验收为 Node.js 选择与安装守卫执行。
