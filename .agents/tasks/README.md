# Task

## 要求

- 需要持续跟踪多步执行、依赖、阻塞或交接时创建 Task。字段、文案等可直接完成的简单修改在会话中说明结果即可；涉及已有任务时更新原记录。
- 同一工作维护一份任务，使用 Markdown TODO 列表。Task 可独立存在，有关联方案时引用 Plan。
- 文件使用具体任务的中文名称，活动任务的正文标题与文件名一致，例如 `通话质量优化.md`。`README.md` 用于本目录要求与模板。
- 每项使用固定 T 编号，写清交付结果和验收条件。状态由 `[ ]`、`[x]` 表达。大项按依赖拆成可独立验收的批次子项，全部子项满足父项验收后勾选父项。
- 关联实现、最小集成和目标环境验收具有独立完成条件时，按实际需要拆为子项并分别记录证据，不固定套用三层结构。完成实现可勾选对应子项，缺环境只阻塞对应验收，不据此勾选父项。
- 每批验收后更新原项：完成项勾选并记录实际证据；未完成项记录剩余工作、阻塞和续接点。依赖、未验证范围按需写在对应项下，中断或交接前保存累计结果。
- 当前批次只指向正在执行及下一步的 T 编号，详细验收、剩余缺口、阻塞和证据只在对应任务项维护；单批任务可省略当前批次。跨领域工作沿用已有统筹任务，没有统筹需要时不另建总任务；关联任务引用同一证据。
- 完成要求：目标行为符合要求，适用的检查通过，受影响文档已同步；检查范围依据项目规则和实际改动确定，命令见根 `AGENTS.md`。未验证项属于本项验收条件时保持未完成，属于其他任务范围时引用对应编号。
- 全部完成后整份移入 `archive/`，文件名加完成日期，例如 `通话质量优化-2026-10-31.md`，不覆盖已有归档。后续工作新建任务并引用归档记录。

## 模板

按实际执行项增减内容，无关联方案、依赖或阻塞时省略对应字段。

```markdown
# 具体任务名称

方案：.agents/plans/具体方案名称.md

## 当前批次

当前执行：T01。续接：完成后进入 T02。

## 交付结果

- [ ] T01 实现具体结果。
  - 验收：明确输入、预期行为和完成条件。
  - 依赖：先完成的任务编号或外部条件。

- [ ] T02 验证关键成功与失败场景。
  - 验收：检查范围与预期结果。
  - 阻塞：缺少的条件及解除条件。
  - 续接：条件满足后的下一步。

- [x] T03 已完成的交付结果。
  - 验收：该项完成条件。
  - 证据：实际命令、结果及必要路径。
  - 范围外验证：如有未执行但属于其他任务的验证，引用对应 T 编号；没有则省略。
```
