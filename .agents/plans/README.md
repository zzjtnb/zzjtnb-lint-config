# Plan

## 要求

- 需要记录设计、比较方案或保留决策依据时创建 Plan，记录问题、目标、范围、依据、设计、取舍、风险和验收标准。实现方式明确的简单修改直接执行。Plan 可独立存在，需要跟踪执行时再关联 Task。
- 文件使用具体方案的中文名称，活动方案的正文标题与文件名一致，例如 `通话连接方案.md`。`README.md` 用于本目录要求与模板。
- 方案正文维护当前已采用的设计、适用条件和待决策事项，使用固定 P 编号；设计变化时同步修订正文，理解当前设计不依赖逐条重放历史变更。正式要求引用所属规范，不在方案复制维护。
- 设计变化按时间记录固定 C 编号，简述原因、关键取舍、影响及被替代决定的引用；存在未决事项或生效条件时明确记录。普通实现进展和检查结果只更新 Task，不为每批改动追加方案记录。
- 采用依据为用户要求、当前正式契约或已核实的项目事实；范围变化时同步更新已关联的 Task。既有 P/C 编号、历史决定及引用保留，修订涉及的设计时将有效结论收拢到正文，失效内容明确标为历史，不借整理改变范围。
- 持续有效且仍需维护的设计沿用原方案；阶段工作及关联任务全部完成、无待决策事项且不再维护时，移入 `archive/`，文件名加完成日期，不覆盖已有归档。新的独立设计另建 Plan，必要时引用历史方案。

## 模板

文件使用具体方案名称，无关联任务时省略“执行”行；无变更时省略“方案变更记录”章节，其他章节按实际设计需要取用。

```markdown
# 具体方案名称

执行：.agents/tasks/具体任务名称.md

## 当前方案

### 问题与目标

P01 当前问题、使用者和预期结果。

### 范围与约束

P02 涉及的模块、外部条件和范围边界。

### 现状与依据

P03 当前代码、正式契约及原始资料，区分事实与假设。

### 具体设计

P04 业务流程、数据归属、模块调用和资源生命周期。

### 关键取舍

P05 采用理由、替代方案及未采用原因。

### 影响、风险与迁移

P06 受影响的使用处、兼容与迁移要求、已知风险。

### 验收标准

P07 功能与失败行为的预期结果，检查要求见 .agents/tasks/README.md。

## 方案变更记录

### YYYY-MM-DD 变更主题

C01 修改／删除／新增：实际填写一种及设计主题。

- 正文：本次修订的 P 编号或章节。
- 替代：被替代的 P/C 编号；新增时省略。
- 原因与依据：需求、当前事实和选择理由。
- 取舍与影响：必要的替代方案、范围或依赖变化。
- 决策或生效条件：存在未决事项或条件时填写；当前已采用设计直接维护在正文。
```
