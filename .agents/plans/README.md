# Plan

## 要求

- 需要记录设计、比较方案或保留决策依据时创建 Plan，记录问题、目标、范围、依据、设计、取舍、风险和验收标准。实现方式明确的简单修改直接执行。Plan 可独立存在，需要跟踪执行时再关联 Task。
- 文件使用具体方案的中文名称，活动方案的正文标题与文件名一致，例如 `通话连接方案.md`。`README.md` 用于本目录要求与模板。
- 原方案使用固定 P 编号；制定后的调整按时间追加“方案变更记录”，使用固定 C 编号，标明修改、删除或新增。保留原决定及既有变更，旧方案无编号时引用原章节。
- 每条变更记录关联决定、调整内容、原因与依据、影响、决策结果及生效条件。决策结果使用已采用、待决策或未采用，保留未采用原因。
- 当前设计以原方案为起点，按时间应用已采用且达到生效条件的变更。采用依据为用户要求、当前正式契约或已核实的项目事实；范围变化时同步更新已关联的 Task。
- 方案相关工作及关联任务全部完成且无待决策变更后移入 `archive/`，文件名加完成日期，不覆盖已有归档。后续调整新建 Plan 并引用归档方案。

## 模板

文件使用具体方案名称，无关联任务时省略“执行”行；无变更时只保留“方案变更记录”标题，章节按实际设计需要取用。

```markdown
# 具体方案名称

执行：.agents/tasks/具体任务名称.md

## 原方案

### 问题与目标

P01 当前问题、使用者和预期结果。

### 范围与约束

P02 涉及的模块、外部条件和范围边界。

### 现状与依据

P03 当前代码、正式契约及原始资料，区分事实与假设。

### 具体设计

P04 业务流程、数据归属、模块调用和资源生命周期。

### 关键取舍

P05 采用理由、替代方案及未采用原因。

### 影响、风险与迁移

P06 受影响的使用处、兼容与迁移要求、已知风险。

### 验收标准

P07 功能与失败行为的预期结果，检查要求见 .agents/tasks/README.md。

## 方案变更记录

### YYYY-MM-DD 变更主题

C01 修改／删除／新增：实际填写一种及设计主题。

- 关联：原 P/C 编号或章节。
- 原决定：原设计及采用理由；新增时按需省略。
- 调整内容：新的设计或取消的内容。
- 原因与依据：需求、当前事实和选择理由。
- 影响：范围、接口、模块和验收条件的变化。
- 决策结果：已采用／待决策／未采用，实际填写一种及依据。
- 生效条件：何时生效、替代哪项决定；未采用的说明原因。
```
